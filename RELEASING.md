# Releasing

Releases are automated by [`.github/workflows/release.yml`](.github/workflows/release.yml):
pushing a tag matching `v*` runs the test suite, builds the sdist and wheel, and creates a
GitHub Release with the artifacts attached. Release notes are auto-generated by GitHub from
merged PR titles, contributor mentions, and a full changelog diff link.

## Tag format

- Stable release: `vX.Y.Z` (e.g. `v1.3.0`)
- Release candidate / prerelease: `vX.Y.ZrcN` (e.g. `v1.3.0rc1`) — note **no hyphen**;
  `v1.3.0-rc1` would be normalized by setuptools to `1.3.0rc1` and fail the
  version-matches-tag check. Prerelease tags are automatically marked as a GitHub prerelease.

## Steps

1. Tag the release commit on `main` and push the tag:
   ```sh
   git checkout main && git pull
   git tag vX.Y.Z
   git push origin vX.Y.Z
   ```
2. Watch the **Release** workflow under the Actions tab. On success, verify the GitHub
   Release: the body should contain the auto-generated PR list with the `.tar.gz` and
   `.whl` attached.

## If the release workflow fails

Delete the tag, fix the issue, and re-push:
```sh
git push --delete origin vX.Y.Z
git tag -f vX.Y.Z <commit>
git push origin vX.Y.Z
```
If a partial release was created, delete it first:
```sh
gh release delete vX.Y.Z --yes
```
